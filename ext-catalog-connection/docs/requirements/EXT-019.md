acceptance:
  - Opening a database, stream or REST connection lists its pieces (tables, topics, endpoints) each with id, name and kind.
  - Each piece shows the uses offered by the installed extensions (for example a dashboard or a process), derived from its kind and facts.
  - An unreachable source, an empty source, a source that needs a declaration and a kind not yet readable show four different messages, never an empty list.
---

What does this source contain, and what is each piece for? Every connector answers in the same
shape: id, name, kind, facts, uses. The uses are contributed by the extensions that consume data (MK-134),
so a product that adds its own consumer adds its own use. Contents are read by the server, which can
reach sources the browser cannot.
